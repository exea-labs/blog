昨日の時点では、<Term id="board">エージェント掲示板</Term>と<Term id="retrieval">ライブラリ</Term>は、それぞれのタスクだけで学習した小さなモデルの中で、おもちゃのタスクを解けていました。ExeaLM は、テキストを読み、ほかのエージェントと話し、調べものをする 1 つのモデルを目指しています。今日は、そのモデルを小さなサイズで、主に実際のテキストで、両方のメモリ回路をオンにして学習しました。そのうえで、回路を作った目的の 2 つのことが、まだできるかを確かめました。

2 つのスキルを同時に教えれば、両方の<Term id="seed">シード</Term>でできます。そこにたどり着くまでに、3 つのレシピが必要でした。言語では、同じ大きさの <Term id="llama">Llama</Term> と互角です。

## 1 つのモデル、4 種類のバッチ

モデルは小さな<Term id="hybrid">ハイブリッド</Term>です。幅 320、6 層で、<Term id="tonn">TONN</Term> 層が第 0 層と第 3 層、残りの 4 層がアテンションです。TONN 層には 10 個の<Term id="circuit">回路</Term>があり、そのうち 1 つが検索回路、1 つが掲示板の回路です。合計で 1,808 万パラメータです。比べる Llama は 1,783 万パラメータで、幅、深さ、語彙、MLP は同じです。

学習の各ステップでは、1 種類のバッチを使います。

- **テキスト**：英語、日本語、コード。4 体の<Term id="swarm">スウォーム</Term>で読みます。
- **Wikipedia**：記事の後半。前半はライブラリに入れます。
- **中継**：<Term id="relay">中継タスク</Term>です。エージェント A が事実を持ち、エージェント B は掲示板を通じてしか答えられません。
- **検索**：<Term id="lookup">検索タスク</Term>です。答えは新しく作った事実のライブラリの中にあります。

どの実行も 32 × 512 トークンを 24,000 ステップ、合計 3 億 9,300 万トークンで、1 台の Mac Studio で回しました。Llama は同じバッチを同じ順番で見ます。言語は、学習に使っていない英語、日本語 Wikipedia、日本語 Web、コードで、<Term id="bpb">bpb</Term> を測ります。中継は、掲示板を共有したときと切ったときで測ります。検索は、モデルが一度も見ていない 1,024 件の事実で、ライブラリを付けたときと外したときで測ります。どちらのタスクも、偶然の正答率は 64 分の 1 です。

## 最初のレシピは言語だけを学び、ほかは何も学ばなかった

最初のレシピは、ステップの 80% をテキスト、15% を Wikipedia、5% を中継に使いました。掲示板への投稿は 64 トークンに 1 回です。24,000 ステップ後、英語は 1.294 bpb に達しました。中継は偶然のまま（1.0%）でした。ライブラリは、学習に使っていない Wikipedia を 1 トークンあたり 0.040 ビット悪くしました。

掲示板は、トークンのまとまりを平均して 1 つの投稿にします。中継の事実は 3 トークンです。64 トークンの平均では、ほとんどが埋め草になります。中継だけの小さなモデルでは、8 トークンごとの投稿で掲示板が 250 ステップで学習しました（掲示板あり 97.4%、切断 1.4%）。16、32、64 トークンの投稿では偶然のままでした。検索も、64 トークンのチャンクに事実が 1 つだけのときは同じでした。各チャンクを 16 件の事実の表にすると、2,000 ステップで 89.6% に達しました。

そこで、次のレシピでは、掲示板への投稿を 8 トークンごとにし、検索の事実を密な表として保存します。Wikipedia のライブラリは、事前の短い確認と同じく、Wikipedia のバッチだけに付けます。

## どちらのスキルを先に教えるかで、もう一方が身につくかが決まる

2 つ目のレシピは、最初の 400 ステップで中継だけを教えました。そのあとステップ 2,000 まで、慣らしの混合を使いました。それ以降は、テキスト 70%、Wikipedia 15%、中継 7.5%、検索 7.5% です。

シード 0 では両方のスキルが身につきました。中継は掲示板ありで 100%（切断で 0.5%）、検索はライブラリありで 90.3%（外すと 0.6%）です。検索が身についたのは遅く、ステップ 6,000 から 9,000 の間でした。シード 1 では中継は身につきましたが、検索は 24,000 ステップのあいだ偶然のままでした。

シード 1 のモデルは、表を見つけられるのに、読めません。ライブラリに 64 個の表があるとき、正しい表が検索の上位 4 件に入るのは質問の 70% です。ランダムなら 6% です。表が 1 つだけで、必ず取り出されるときでも、値は 1 つも当たりません。

最初の 400 ステップだけを変えて、ステップ 2,000 まで短く確かめると、理由がわかりました。

| 最初の 400 ステップ | 中継、共有 / 切断 | 検索、あり / なし |
|---|---|---|
| 中継だけ | **99.95%** / 1.6% | 1.4% / 1.4% |
| 検索だけ、そのあと中継だけ | 2.1% / 2.1% | **74.6%** / 1.4% |
| 両方を同時に | 94.2% / 1.0% | 67.9% / 1.5% |

先に単独で身についたスキルが、もう一方をふさぎます。検索のあとでは、中継は始まりませんでした。中継のあとでは、検索は一方のシードで遅れて始まり、もう一方では始まりませんでした。同時に教えると、どちらも 1,000 ステップ以内に始まります。

3 つ目のレシピは、ステップ 0 から両方を同時に教え、ほかは 2 つ目と同じにしました。両方のシードで、両方のスキルが身につきました。

| レシピ | シード | 中継、共有 / 切断 | 検索、あり / なし | 英語 | コード |
|---|---|---|---|---|---|
| 中継を先に | 0 | 100.0% / 0.5% | 90.3% / 0.6% | 1.316 | 1.606 |
| 中継を先に | 1 | 100.0% / 1.8% | 1.4% / 1.4% | 1.326 | 1.644 |
| **両方を同時に** | 0 | **100.0%** / 0.9% | **94.0%** / 1.5% | 1.320 | 1.612 |
| **両方を同時に** | 1 | **100.0%** / 1.0% | **94.3%** / 1.7% | 1.328 | 1.636 |

検索は、ステップ 3,000 までに 77%（シード 0）と 80%（シード 1）に達しました。中継を先に教えるレシピは、その時点でまだ偶然のままでした。言語は、シードによるばらつきの範囲で、中継を先に教えるレシピと同じです。使うべきレシピはこれです：`--schedule "400:0,0,0.5,0.5;2000:0.3,0.2,0.25,0.25"`。

## 学習したモデルが実際にすること

`experiments/show_skills.py` は、両方のスキルを人が読める形で表示します。これは 3 つ目のレシピのシード 0 のモデルです。キーと値は合成トークンで、K と V の番号で表しています。

```
RELAY: agent A reads the facts, agent B is asked for them. Only the board connects them.
  agent A reads:  K01 -> V39   K57 -> V35   K24 -> V60   K27 -> V26
  agent B is asked     answer   board shared   board cut
  K27 ?                V26      V26 ok         V32 --
  K01 ?                V39      V39 ok         V13 --
  K24 ?                V60      V60 ok         V26 --
  K57 ?                V35      V35 ok         V26 --

LOOKUP: a library of 64 tables (1024 facts) the model has never seen.
  key        answer   library attached   library removed
  K02 K46    V63      V11 --             V30 --
  K46 K14    V15      V15 ok             V48 --
  K61 K56    V00      V00 ok             V59 --
  K17 K40    V25      V08 --             V48 --
  K39 K60    V10      V10 ok             V52 --
  K29 K23    V63      V63 ok             V57 --
  K07 K39    V15      V15 ok             V46 --
  K01 K29    V21      V21 ok             V59 --
  ... 8 more keys in this list

over 50 more examples of each (chance is 1 in 64):
  relay:  board shared 100.0%, board cut 2.5%
  lookup: library attached 94.6%, library removed 1.9%
```

掲示板を切ると、エージェント B は当て推量をします。2 回、V26 をくり返しています。これは、自分のテキストの中で最初の質問のあとに出てきた答えです。ライブラリを外しても、モデルは値のトークンで答えますが、正しい値ではありません。出力は `results/full_small/show_skills_exealm_skillsA_seed0.txt` にあります。

## 言語：同じ大きさの Llama とほぼ互角

ステップ数をそろえ、同じバッチで、それぞれ 2 シードです。

| モデル | シード | 英語 | 日本語 Wikipedia | 日本語 Web | コード | 平均 |
|---|---|---|---|---|---|---|
| ExeaLM | 0 | **1.320** | **1.422** | **1.322** | **1.612** | **1.419** |
| Llama | 0 | 1.339 | 1.444 | 1.336 | 1.641 | 1.440 |
| ExeaLM | 1 | **1.328** | 1.428 | **1.318** | **1.636** | **1.427** |
| Llama | 1 | 1.332 | **1.426** | 1.319 | 1.637 | 1.428 |

ExeaLM は、シード 0 で 0.021 bpb、シード 1 で 0.001 上回り、平均で 0.011 です。Llama のシード 1 はシード 0 より 0.012 良く、ExeaLM のシード 1 は 0.008 悪い値です。

この比較は、ExeaLM に有利です。ステップの 15% が中継と検索のバッチです。ExeaLM はそこから学びますが、Llama にとってはノイズです。どちらのモデルもスキルを身につけなかった最初のレシピでは、ステップ数をそろえると Llama が ExeaLM と並ぶか上回りました。英語は 1.294 対 1.294、コードは 1.558 対 1.581 です（Llama が先、1 シード）。

ExeaLM は、Mac で 1 ステップあたり 1.30 倍の時間がかかります（6,414 秒対 4,942 秒）。そこで、ステップ数ではなく時間をそろえて Llama を学習しました。中継を先に教えるレシピのシード 0 で、ExeaLM の 24,000 ステップに対して 31,200 ステップです。結果は互角で、Llama が 1.414 bpb、ExeaLM が 1.416 です。余分な 30% がどこにかかっているかは、まだ計測していません。おそらく、8 トークンごとの掲示板への投稿と検索です。どちらも素の PyTorch で動き、アテンションは 1 つの融合カーネルで動きます。

実際に学習する予定の大きさでは、言語の結果は ExeaLM にもっと有利です。メモリ回路なしの 0.1B ハイブリッドは、計算量をそろえた比較で、同じ大きさの Llama を 2 シードの平均で 0.024 bpb 上回ります（[0.1B の結果](/ja/posts/hybrid-beats-llama/)）。どちらも短い実行で、それぞれ約 5,000 万トークンです。

## プロジェクトの現状

<CardList>

- **掲示板**は、17M で中継ができます。共有で 100%、切断で 1%、両シードです。実際のテキストでは、スウォームとして学習する効果が再現しませんでした。昨日は、対応する対照より 0.012 bpb 良いと報告しました。シームの修正後に実行し直すと、スウォームは対照より 0.033 から 0.035 悪くなりました（両シード）。修正をオフにして実行し直すと、両者は互角でした（1.628 対 1.627、1 シード）。512 個中 1 個のターゲットを隠すだけでは、これほど大きな振れは説明できません。同じ実行が Mac の GPU で 2 回同じ答えを出すかを確かめています。それまでは、実際のテキストでのスウォームの効果は未確認です。昨日の記事への訂正は、このあと出します。
- **ライブラリ**は、見たことのない事実で機能します。94% 対 1.6%、両シードです。実際の Wikipedia では、まだ何も得られていません。最後の値は 1 トークンあたり -0.072 と -0.011 ビットで、シード 0 ではステップ 21,000 で -0.48 まで振れました。検索が正しい記事を見つけるのは 26% です。これは [issue #22](https://github.com/exea-labs/ExeaLM/issues/22) です。
- **Llama との比較**では、ExeaLM は 17M の言語で互角、0.1B ではメモリ回路なしで上回ります。メモリ回路ありの 0.1B は、まだ学習していません。

</CardList>

## この記事が示していないこと

- **スキルが実際の問題で役に立つこと。** 中継と検索は、ランダムなキーと値を使います。テキストで学習したモデルの中で回路が動くことは示せます。実際の文書でエージェント同士が得をするかは、まだわかりません（上の掲示板の項目）。
- **規模。** 1 つの大きさ（18M）、2 シード、3 億 9,300 万トークンです。計算量をそろえた比較は 1 シードだけです。
- **きれいな言語の比較。** 合成バッチは、ExeaLM より Llama に損をさせます。テキストと Wikipedia だけで学習する Llama をキューに入れました。2 つのスキルが言語にどれだけのコストをかけるかを測ります。
- **速度。** ExeaLM は 1 ステップあたり 1.30 倍遅く、Mac の GPU 1 つで、コンパイルなしで測ったものです。

## 次にやること

- **0.1B で同じレシピ**を 3,000 ステップ回し、実際の大きさで両方のスキルが身につくかを見ます。Mac Studio のキューに入っています。
- **回路の探索**をオンにし、学習の混合データで回路を評価します。スキルに必要な回路を落とさないためです。その次にキューに入っています。
- **より強いベースライン。** テキストだけの Llama、次に Gated DeltaNet 層を持つ Qwen3.5 型のハイブリッドです。再帰型の層とアテンションを組み合わせた、小さなオープンモデルの中でもっとも強い設計です。
- **実際のテキストでの検索**（[#22](https://github.com/exea-labs/ExeaLM/issues/22)）：正しい記事を見つける検索です。
