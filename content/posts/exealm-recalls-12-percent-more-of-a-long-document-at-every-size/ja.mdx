これまでの比較はすべて<Term id="bpb">バイトあたりビット数</Term>、つまり評価用の文章にモデルがどれだけ驚くかで測ってきました。ExeaLM はすべての評価セットで私たちの Qwen3.5 型を上回ります。そのリードは、短い窓より長い文書のほうが大きくなります（[前の記事](/ja/posts/exealm-now-keeps-one-tonn-layer-in-the-middle-at-0-1b-it-leads-our-qwen35-style-build-on-every-held-out-set/)）。けれども研究やコードのアシスタントは、驚きではなく正確な答えで評価されます。この記事では、長い文書でのリードが正確な答えになるかを確かめます。あわせて、ExeaLM のどの部分がそれを担っているかも確かめます。

## 完全一致で採点する 3 つのタスク

学習を終えたすべてのモデルに、評価用の文書の最初の 4,096 トークンを、セットごとに 64 文書、512 トークンの窓 8 つの<Term id="read-stream">ストリーム</Term>として読ませました。対象のすべてのトークンで、直前までの正しい文章を与えたときのモデルの第一候補が正しければ、<Term id="exact-match">完全一致</Term>として数えます。貪欲デコードでその部分を書いたときと同じ結果です。

- **想起**（文章とコードの 9 セットすべて、対象 11,614 個）：文書の前のほうに出た 6 トークンの並び。最初の 2 トークンが手がかりで、後の 4 トークンが対象です。この並びが最後に出たのは 1 つ前の窓より前なので、読んでいる窓にも、アテンションが引き継ぐキーとバリューにも入っていません。
- **コードの次の行**（コードの 4 セット、対象 12,092 個）：1 つ前の窓より前に最後に出た識別子を使う行。RepoBench の次の行のタスクを、同じファイルの離れた文脈で行うものです。
- **<Term id="pass-key">パスキー</Term>**（深さごとに 64 試行）：評価用の Wikipedia の文章に「The pass key is 48213. Remember it.」を埋め込み、最後の窓に「What is the pass key? The pass key is」を置きます。RULER と同じ形です。

## どの規模でも、どのタスクでも ExeaLM が上

ストリームとして読んだときの完全一致の割合（シードの平均）：

| | 想起 | コードの次の行 | パスキー、同じ窓 | パスキー、1 つ前の窓 |
|---|---|---|---|---|
| **0.1B、パラメータあたり 111 トークン**（2 シード） | | | | |
| ExeaLM | **0.268** | **0.042** | **0.648** | **0.078** |
| Qwen3.5 型 | 0.235 | 0.038 | 0.047 | 0.000 |
| **0.25B**（3 シード。素の Llama は 1 シード） | | | | |
| ExeaLM | **0.241** | **0.035** | **0.766** | **0.281** |
| Qwen3.5 型 | 0.215 | 0.032 | 0.016 | 0.000 |
| 素の Llama | 0.134 | 0.019 | 0.000 | 0.000 |
| **0.5B**（2 シード） | | | | |
| ExeaLM | **0.282** | **0.045** | **0.859** | **0.266** |
| Qwen3.5 型 | 0.252 | 0.042 | 0.188 | 0.000 |
| 素の Llama | 0.186 | 0.027 | 0.000 | 0.000 |

どの対象も両方のモデルで採点したので、差は対象ごとに検定しました（McNemar 検定、シードはまとめて）。ExeaLM は 0.1B、0.25B、0.5B で、Qwen3.5 型より 13.9%、11.9%、11.7% 多くの対象を想起しました。どの規模でも p は 1e-40 未満です。コードの行は 10.2%、8.5%、6.5% 多く書けました（p = 2e-5、3e-5、0.002）。読んでいる窓の中のパスキーは 0.65、0.77、0.86 の割合で見つけ、Qwen3.5 型は 0.05、0.02、0.19 でした（p は 1e-16 未満）。

想起のリードは、0.1B から 0.5B まで 12% から 14% のままです。同じ範囲で、短い窓を 1 つずつ読んだときの ExeaLM のリードは、バイトあたりビット数で 2.8% から 0.6% に縮みます。モデルが大きくなっても残るのは、長い記憶のリードです。

## TONN 層が加えるもの

この実験では、ExeaLM のただ 1 つの <Term id="tonn">TONN</Term> 層をアテンションに置き換えたモデルも、同じストリームとレシピで学習しています。想起とコードの次の行では、両者は互角です（差は 1.3% 以内、0.25B で p = 0.15 と 1.0）。パスキーは違います。1 つ前の窓では、ExeaLM は 0.281 の割合で見つけ、置き換えたモデルは 0.094 でした（0.25B、3 シード。ExeaLM だけが当てた試行は 38、その逆は 2、p = 3e-8）。読んでいる窓の中では、ストリームとして読んだとき 0.766 と 0.635 でした（p = 6e-4）。

状態を引き継がずに窓を 1 つずつ読むと、両者は近くなります（0.677 と 0.609、p = 0.10）。TONN 層が加えるものは、窓から次の窓へ運ばれます。それがこの層を作った目的です。ふつうの文章では、アテンションだけのモデルと ExeaLM は互角です（結果の 24 節）。TONN 層が 9B に残るのは、ライブラリの検索、掲示板、重みの書き換えが TONN の回路だからです。アテンションの層はそれを持てません（[決定事項、11 月 27 日](https://github.com/exea-labs/ExeaLM/blob/nairr/docs/decisions.md)）。

## 2 倍の長さの文書でも同じ結果

8,192 トークンの文書（窓 16 個、セットごとに 48 文書、深さごとに 32 回のパスキー試行）でも、3 倍の対象数で同じ結果になりました。ExeaLM は 0.1B、0.25B、0.5B で Qwen3.5 型より 11.0%、13.9%、10.6% 多く想起しました（どの規模でも p は 1e-50 未満）。コードの行は 8.5%、7.5%、2.8% 多く書けました（p = 6e-6、6e-8、0.03）。1 つ前の窓のパスキーは 0.09、0.25、0.28 の割合で見つけ、Qwen3.5 型は 0 でした。アテンションに置き換えたモデルとは、ここでも想起とコードで互角です。1 つ前の窓のパスキーは、0.25B で 0.250 と 0.052 でした。

## 2 つ前の窓には届かない

2 つ以上前の窓のパスキーを見つけたモデルはありません。どの深さ、どのモデル、どの規模でも 64 回中 0 回です。ライブラリでも同じ限界が見えます。0.1B のモデルで、ライブラリの項目を質問の 1 つ前か 2 つ前の窓に置きました（1 シード、評価用の質問 1,195 個）。1 つ前の窓なら、どのモデルも、項目を質問と同じ窓に置いたときの効果の約 90% を保ちます。2 つ前の窓では、どのモデルにも何も残りません。どのモデルも、項目がないときより悪くなります。この規模では、遠くから正確に取り出すことはまだできません。使わせたい文章は、質問と同じ窓か、その 1 つ前に置きます。

## 3B では、リードはまだ出ていない

3B の組を、45,688 ステップ中のステップ 16,000 で凍結しました。ExeaLM のストリームの段階はステップ 36,550 付近から始まるので、その前です。どちらのモデルもまだストリームで学習していません。ストリームとして読むと、ExeaLM の想起は 0.281、Qwen3.5 型は 0.286、コードの行は 0.046 と 0.048 で、互角です。読んでいる窓の中のパスキーでは、まだ ExeaLM がリードしています（0.48 と 0.17）。小さい規模では、想起のリードはストリームの段階とともに現れました。この確認はそれを決めるには早すぎます。決めるのは、11 月 29 日の深夜 0 時ごろに学習を終える 3B の組です。

## この結果が示さないこと

- これは教師強制のもとでの完全一致です。モデルは各対象の直前まで正しい文章を見ています。貪欲デコードでその部分を書いた結果と同じですが、長い答えを自由に書いた結果ではありません。
- この実験では、Qwen3.5 型と素の Llama はストリームで学習しません（[決定事項、11 月 25 日](https://github.com/exea-labs/ExeaLM/blob/nairr/docs/decisions.md)）。そのため、引き継いだ状態からの得が小さくなります。素の Llama は、ストリームで読むと 1 つずつ読むより悪くなります。アテンションだけのモデルは ExeaLM と同じくストリームで学習するので、TONN 層を公平に確かめる比較対象になります。
- この規模では、コードの完全一致の割合は 3% から 5% と低めです。差は有意ですが、小さなモデルです。
- 規模ごとに 2〜3 シードです。0.1B のアテンションだけのモデルと 0.25B の素の Llama は 1 シードです。
- 学習を終えた最大のモデルは 0.5B です。上の 3B の確認は、学習の 3 分の 1 の時点のチェックポイントです。

## 次に

3B の組は 11 月 29 日の深夜 0 時ごろに学習を終えます。そのあと、ストリームの段階を終えた ExeaLM で、同じ 3 つのタスクを走らせます。次の記事では、この日のもう半分を書きます。ExeaLM とそのライブラリを、Qwen3.5-9B を含む公開モデルと比べた結果です。
